# Earth draft: exploratory road across the horizontal seam

`MapFormat.PreparesExternalToroidalSeamRoad` opens an explicitly supplied
VMAP, searches for the longest symmetric clear land segment up to three tiles
on each side of the horizontal seam, and uses the map editor's road operation
to draw dirt road. It excludes blocked, visitable, existing-road and river
tiles, then saves and reloads the map and compares the selected road types,
directions and flags. The output must not already exist. This opt-in test does
not distribute the map or its assets.

On macOS arm64, the binary built from `c5ade84` plus the test committed as
`89dfd95` passed with the isolated Earth mod profile and the Earth draft
SHA-256 `58e7b7e6bf94c117d350028757c9cf1c7160bf3107fe435cf003306d3dbd74a6`.
The first qualifying site was row 425, with only two qualifying cells:
`(251,425,0)` and `(0,425,0)`. The final saved local test map SHA-256 is
`a8897652c82f1a44ff1d90a620420b5e288ab7b2a123978e4b42d4831968973c`.
The local files are under TB5 `runtime/earth-map-research-2026-11-15/`.

## Search for connections to existing dirt roads

The optional `VCMI_EARTH_CONNECT_ROAD` audit added in `88bcd90` searches
candidate horizontal seams in descending lengths of up to three clear cells
per side. From each endpoint it searches eight-direction paths to an existing
dirt road without crossing the map boundary, traversing water, blocked or
visitable cells, rivers or roads of other types. Each step must also pass
`CMap::canMoveBetween`. The search does not account for guards or prove that
a full game route or road artwork would be valid.

With the source Earth draft and `VCMI_EARTH_EXPECT_NO_CONNECTION=1`, this
audit passed its negative expectation: it found two qualifying segment
candidates, with zero right-edge endpoints and one left-edge endpoint able
to reach an existing dirt road under those constraints. The XML is on TB5 at
`runtime/earth-road-connection-audit.xml`. A positive control on the synthetic
`toroid-road-axes-clean-2026-11-15.vmap` found a six-cell seam segment and an
adjacent dirt-road connection on each side, then saved and reopened its output.
The original isolated-fragment preparation also passed again on Earth.

These results do not rule out a connection using a different road type,
water, a relocated decorative object, a changed terrain cell or a broader
redesign. No connected Earth map was generated by this search. Inspect the
actual obstacles before choosing an adaptation.

The search was subsequently widened in `2f93b86` to accept an existing road
of any type as a destination; it still does not traverse an existing road of
a different type. The Earth audit again found two candidates, zero connected
from the right edge and one from the left; the synthetic road-axes positive
control still passed. The newer Earth XML is local to TB5 at
`runtime/earth-any-road-audit.xml`.

A read-only inspection of the serialized footprint masks near row 425 found
`cactus_7575` blocking `(250,425,0)`, `yuccaTrees_7567` blocking
`(251,424,0)`, and `mountain_7577` blocking cells south of the seam. A
two-way monolith, `monolithTwoWay_5267`, has its visitable cell at
`(250,429,0)`. These coordinates are a geometry estimate from the saved
templates, not an engine-verified route. The monolith has restricted approach
directions, and reaching it may require an object or terrain edit; neither a
valid approach nor a road connection to it has yet been established.

## Minimal obstacle experiment on the current assembled map

On the later assembled Earth map, SHA-256
`97f5222ab48e5987b58c12643be985e450524488bf042a9f6ae27ab9f03ea1f3`,
an exploratory worktree-only variant of the connection audit removed the
non-visitable `cactus_7575` from the in-memory map after confirming that it
blocked `(250,425,0)`. The original map was not changed. With the existing
search constraints, the test found four candidate seam segments: three had
a connection on the left side and none had one on the right. It failed its
positive connection assertion and wrote no output map. The macOS arm64
`vcmitest` binary was built from `8ca4678` plus this temporary experiment;
the XML is local at TB5 `runtime/earth-road-cactus-test.xml`.

Removing this cactus alone is insufficient under that search algorithm. This
does not exclude a connection after other map edits or under less restrictive
rules. The temporary experiment was removed; the connected Earth road remains
open. A separate Crossroads fixture already demonstrates a road at a seam,
as described in [the graphical record](topology-preview-f0f7f4a-2026-11-15.md).

An additional worktree-only run removed `cactus_7575`, `yuccaTrees_7567`
and `mountain_7577` in memory after checking that each was non-visitable.
On the same assembled Earth map, the constrained search found nine candidate
segments; eight had a left-side road connection and none had a right-side
connection. Its positive assertion failed and no map was saved. The test
binary was built from `d8584d1` plus the temporary experiment; the XML is
`runtime/earth-road-three-objects.xml` on TB5. The experiment was removed
afterwards. This result suggests that clearing these particular decorations
is not sufficient; it does not prove that no connection is possible with
other terrain, object or route changes.

## Road extension from the existing network

`MapFormat.PreparesEarthConnectedSeamRoad`, added in `4b2ddaa`, creates a
separate copy of the assembled Earth map. It verifies and removes one
non-visitable decoration, `cactus_7575`, blocking `(250,425,0)`; checks the
four proposed cells for land, obstacles, interactive objects and rivers; and
uses the map editor's road operation to extend the existing road at
`(2,425,0)` along `(1,425,0)`, `(0,425,0)`, `(251,425,0)` and
`(250,425,0)`. The opposite endpoint is not connected to a second existing
road network. The generator verifies bidirectional adjacent movement geometry,
the existing road and the saved/reopened road types. It requires explicit
`VCMI_INSPECT_START_VMAP` and `VCMI_EARTH_SEAM_ROAD_OUTPUT` paths, refuses an
existing output, and does not modify the source.

On macOS arm64, this test passed against the assembled input SHA-256
`97f5222ab48e5987b58c12643be985e450524488bf042a9f6ae27ab9f03ea1f3`.
The generated local file `draft-stacked/earth-connected-seam-road-verified.vmap`
under the TB5 Earth research runtime has SHA-256
`61f9f042612fb86aa611c64e57b2c2e6ee7a39409cf2b4eeb1fd74b8b00d40b7`.
Two generated archives had identical member contents, though their archive
hashes differed. `VCMI_INSPECT_EARTH_SEAM_ROAD` in the existing external-map
game test initialized the first copy and staged a red hero at the existing
road. The server moved the hero along the entire five-cell route and back,
including both seam directions, while consuming movement points; all route
cells were unguarded in that initialized state. The two converted portal
pairs also passed the existing initialization check. The test build used
`a586abb` plus `4b2ddaa`; XML results are `runtime/earth-connected-seam-road-final.xml`
and `runtime/earth-connected-seam-road-game.xml` under the TB5 build root.

The local Earth profile still points to the previous assembled map. This road
candidate has not been checked in a graphical client, so its static appearance
and integration into the playable demo remain open. The staged route does not
prove a normal starting hero can reach it or that map balance is preserved.

## Isolated graphical fixture

`tools/stage_earth_seam_road.py`, added in `bf8d056`, creates a new local
fixture from the road candidate. It validates a SHA-256 over sorted ZIP
member names and contents, avoiding dependence on archive timestamps, and
requires the expected red hero and initial anchor. It changes the hero anchor
from `(165,353,0)` to `(1,425,0)` and renames the scenario to `Earth Seam
Road QA`. On the documented fixture this places the hero's visitable tile at
`(0,425,0)`. It refuses to overwrite an existing output.

The local fixture is under TB5 at
`runtime/earth-seam-road-qa-profile/Maps/earth-seam-road-qa.vmap`, SHA-256
`cde4d4d42cc2cf40b53b3a88782a6e55c4cf0ce378d1b19ee19c808c62d12fb8`.
A semantic comparison confirmed that only the named hero's coordinates and
the scenario name changed; all other ZIP members were byte-identical. The
external-map initialization and staged server road route passed with this
fixture and its separate HotA profile; XML is
`runtime/earth-seam-road-qa-profile/initialization.xml` on TB5. A local
`Start Earth Seam Road QA.command` points at that profile and sets the build
working directory; its shell syntax was checked. The profile links to the
local game resources and keeps its own configuration and saves.

This prepares, but does not prove, the graphical seam view: neither the new
launcher nor the fixture has been operated in a graphical session. The
ordinary Earth demo profile remains pointed at the prior map.
